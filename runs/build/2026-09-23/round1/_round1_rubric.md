# 第一轮扫描 · 抽取判据（所有批次统一遵守）

## 角色
内容提炼助手，不是创作者。**只提取原文中出现的要素**，不发挥、不联想、不补常识。

## 三层判别

| 层 | 判据 | id 形式 |
|---|---|---|
| 场景 | 文章在回答的"如何…"问题；有明确触发情境和目标产出 | 必须以"如何"开头 |
| 概念 | 思维方法/认知原理/分析操作。**核心判据：能否写出 IPO（输入→处理→输出）或拆成 2-6 个子步骤** | 中文名，不带"概念""方法"后缀 |
| 实体 | 具体的人/物/工具/产品/具名框架模型。**判据：能被"我用了 XX"引用，且 XX 不是思维动作本身** | 中文名 |

### 概念 vs 实体 的边界（容易错）
- 通用思维动作 → 概念：归纳、演绎、分解、抽象、MECE、结构化思维、假设验证
- 具名的、由特定人/组织提出的方法论产品或可视化框架 → 实体：麦肯锡七步法、金字塔原理、SBR模型、鱼骨图、PDCA、二八法则、SOA
- 书籍、人物、组织、软件工具 → 实体

## 每篇要提取什么
1. **场景**：0-3 个。只提文章真正回答的问题，不要为每个小节都造一个场景。
2. **概念**：3-8 个。拿不准时问自己"能写成 IPO 吗"，能 → 概念；不能但又是具名东西 → 实体。
3. **实体**：2-8 个。人物/书籍只在**文章明确提及且对论点有实质作用**时才收（不能只因为"提了一嘴"）。

## 粒度红线（违反即作废）
- 不提"XX能力""XX意识""XX水平"这类空壳名词（如"独立思考能力"→ 提"独立思考"）
- 不把同一概念的动词/名词变体拆成两个（"结构化表达/结构化输出"→ 只留一个）
- 不把组合概念与它的子概念重复登记（"XX与YY"这种并列短语，通常拆成两个独立概念即可，不必再登记组合项）
- 场景不要太窄（"如何用 XX 工具做 YY 具体任务"）也不要太宽（"如何思考"）

## 字段要求
- `id`：简洁中文名
- `define`：≤50 字，**尽量使用原文核心措辞**，只说"是什么"，不评价重要性
- `sources`：`raw/文件名.md`（原文相对路径，禁止绝对路径/反斜杠）
- 概念额外给 `type`：思维方法 / 认知原理 / 分析操作 / 知识管理 / 学习理论 / 管理学原理 / 哲学概念 / 通用框架
- 实体额外给 `category` + `type`：
  - category：工具与平台 / 框架与模型 / 人物与组织 / 知识资产 / 技术与标准
  - type：工具 / 产品 / 技术 / 标准 / 模型-框架 / 人物 / 组织 / 书籍 / 概念实体

## 输出格式（写入 model/_round1_batchN.md）

```markdown
# 批次 N 抽取结果

## 处理文件
- raw/xxx.md
- raw/yyy.md

## 候选场景
| id | define（一句话，≤50字） | sources |
|---|---|---|

## 候选概念
| id | type | define（一句话，≤50字） | sources |
|---|---|---|---|

## 候选实体
| id | category | type | define（一句话，≤50字） | sources |
|---|---|---|---|---|

## 存疑项（拿不准归类的，单列出来说明）
| 候选名 | 倾向归类 | 存疑理由 | sources |
```

## 硬规则
- 每篇必须产出三个表，允许为空但必须写明"（本文无明显实体）"
- sources 必须是你**实际读过的那篇文章**的文件名，禁止张冠李戴
- 同一批次内 id 不要重复；跨批次重复是**正常的**（后续统一去重），不要自行合并别的批次的
- 宁可多提（后续合并），不可遗漏
