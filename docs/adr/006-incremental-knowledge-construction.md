# ADR 006：增量知识建设与统一 Agent 操作

日期：2026-10-08。状态：Accepted。

## 背景

原知识由人定义框架、Agent 纵览提取、人审搭建；v1.4 提供应用与维护入口，但新 Raw 到正式模型缺少可重复的任务、比较和发布流程。用户要求按接入资料、候选比较、审查和更新闭环推进，并能定位文档、让 Agent 定向操作。完整知识字段参与问答明确延后。

## 决策

- 延续 Scenario/Concept/Entity 与现有文件模型，不用新领域案例强制改变类型和字段。
- 两轮处理：先忠实原文，再比较已有完整节点。每项观察必须有建议归宿，保留冲突与不纳入理由。
- 准入与处理状态分开。任务冻结原文和三模型基线；来源变动或模型变动阻止旧候选发布。历史有引用资料使用 manifest 兼容基线，不补造审查。
- GUI 和 CLI/HTTP 共用 KnowledgeBuild.execute。根目录 AGENTS.md、操作契约 tools、Agent 指南和人用文档共同定位模块。当前不安装个人 Skill 或 MCP。
- 发布只应用已通过候选并校验依赖，只替换受影响 YAML 条目，支持部分发布。完整完成才更新资料处理哈希。
- 共用跨进程写锁，写入前保存多文件 before/after 清单；失败补偿、中断安全恢复，外部修改拒绝覆盖。单文件替换原子，多文件依靠日志恢复，不宣称跨文件数据库事务。
- 支持登记复用现有段落身份、字段哈希与检索状态。merge 保留 id 并登记别名，本期不改变问答召回。

## 代价与边界

本期由外部桌面 Agent 执行语义提取和比较，程序只验证结构、原文位置、引用与版本。整模型文件基线检查偏保守，其他节点修改也会要求新任务。没有自动来源删除传播、框架迁移、PDF/OCR、定时后台 Agent 或候选语义评测。

多文件意外中断可能需要手动解除确认已停止进程的写锁，再执行 recover。恢复遇到外部修改保留现场。已提交发布的纠错用新候选或 Git，不提供无条件整库回滚。

## 验证与使用

操作见 docs/knowledge-construction.md 和 application/agent-operations.md。工程验证见 runs/build/studio-v1.5/verification.md；语义支持与最终回答效果仍需人工评测。ADR 002 的先验证应用后 MCP 路线与 ADR 005 的一跳边界继续适用。
