# ADR 005：一跳为主、人工证据统一与可回放运行记录

- 状态：Accepted
- 日期：2026-10-03
- 依据：用户确认开始 v1.4，并纳入第一批内容；先按程序目前的一跳理解，GUI 提前展示多跳思路和路径。

## 决策

主界面从一跳检索开始：问题匹配场景 → 取场景阶段直接引用知识 → 在相关来源中检索原文。保持原有场景匹配规则和最多 12 个知识项的上下文预算，不把关系探索当作逐步语义推理。完整场景阶段仍可查看。

可继续多跳的路径仅预览明确的出向引用：从本次取到的直接知识出发，展示场景没有直接引用的后续节点。预览不检索后续节点原文，不把它们加入本次上下文，不创建另一次运行。点击“用此路径开始探索”只填写多跳表单；主动提交后执行现有有界 BFS 并保存独立 trace。本轮没有采用第二批语义重排、自动跳数或路径评分重构。

段落身份、来源版本和人工支持状态由 scripts/kb_evidence.py 统一。人工记录保存支持字段、该字段内容哈希、来源哈希、原文快照、时间和可选理由。字段可为定义、IPO、阶段规则、具体引用位置等；登记不意味着节点所有内容正确。旧记录保留为待补充复核，不能静默升级为已审字段；来源或支持字段变化后，旧确认不参与有效确认排序。

GUI 证据、问题上下文、Raw 对照和多跳终点使用同一登记。已确认和候选去重。相关段落仍由原有词语匹配评分；问题词语命中且确认有效时加 0.05 的有限偏好，确认不替代问题相关性，不是正确概率。

## 全局视图

完整加载场景、概念和实体，保留独立节点；按类型圆环排布仅用于可读性，不表达层级。相同起点、终点、关系的重复引用聚合，仍保存全部字段位置。场景—知识矩阵只统计阶段直接 uses，证据覆盖只统计已审支持范围；运行使用次数按每条 trace 中出现过的节点去重计数，不能等同于业务效果。

历史运行可叠加到当前图中定位；当前模型和历史快照不一致时，历史事实仍以记录为准。

## 运行与评价

scripts/kb_trace.py 统一 GUI 问题查询、GUI 多跳和 CLI 保存。使用微秒时间与随机 ID，指定已有 ID 会拒绝覆盖。旧 trace 可只读回放，缺少元数据时明确显示未记录。普通节点搜索、浏览、段落定位不单独生成问题 trace。

每次保存查询参数、上下文/路径/段落快照、版本与哈希、程序检索耗时。哈希包含模型、来源清单、证据登记、检索相关代码和已准入来源内容；前后版本不同会标记复核。耗时不含 trace 落盘与网络传输。它是历史结果回放，完整原版本重跑仍需保留 Git 或对应文件版本。

GUI 评价记录场景是否合适、证据是否充分、结果是否有用与说明，复用原有反馈文件和待审队列。重复提交相同评价不重复创建项目，版本冲突拒绝旧窗口覆盖。队列审查状态保留；修改评价后重回待审。队列同步失败时，已保存评价保留，界面说明部分成功并支持刷新后再次保存重试。评价和查询均不修改正式模型。

## 后果与边界

继续标准库 HTTP、静态前端和现有 PyYAML，不引入模型 API、向量库、图数据库、Flask 或运行时 npm。查询采集与人工评价提供工程可观察性，不证明一跳或多跳答案准确性提升。最终回答仍由外部 Agent 组织，程序不自动采集最终回答或评价其真实性。

已有数据通过 apply_update.py 保留；没有强制数据迁移或需要删除的旧目录。工程验证与未验证环境见 [验证报告](../../runs/build/studio-v1.4/verification.md)。
