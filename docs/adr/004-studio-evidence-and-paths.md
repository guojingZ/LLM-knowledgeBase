# ADR 004：本地工作台、证据登记和明确引用路径

- 状态：Accepted
- 日期：2026-10-02
- 依据：用户明确要求继续迭代并直接交付 v1.3；原始 `model/` 和 v1.0.0 合并包代码已核对。

## 决策

维护 GUI 合入同一项目，只监听本机。使用 Python 标准库 HTTP + 原有 PyYAML，静态 HTML/CSS/JS，不增加 Flask/npm/图数据库/远程模型依赖。`model/*.yaml` 保持正式节点唯一权威，人工确认的段落绑定进入 `registry/gui_evidence.yaml`，索引在内存计算，保存历史进入 `runs/gui/history/`。

关系仅由明确结构字段建立，正文提及和共享来源不造边。BFS 只解释引用路径，反向展开单独标注；段落召回与人工确认分离。限深度、节点数、展开数，返回截断状态。

保存通过差异预览、整文件哈希、节点结构与引用校验、唯一备份、原子替换执行。回滚仅在当前文件等于该次保存结果时允许。已有知识与 Git 状态通过 `apply_update.py` 保留。

## 替代方案与后果

- 继续 Flask：原 v1.0.0 未经过实际启动验证且增加依赖；标准库足够承载当前本地规模。
- 正文包含关系：会混淆提及、同名和真实引用，已弃用。
- 自动建立段落支持结论或调用 LLM：未具备人工金标准和模型 API 授权，不纳入当前交付。
- 多人数据库：当前单机 YAML 项目不需要。外部编辑与 GUI 无共享文件锁，提交前哈希能识别一般冲突，建议单一编辑入口；不承诺多人并发写入。

ADR 002 的 GUI/本机 HTTP 延后条款在本轮被替代，回答质量评测与 MCP/Skill 的限制继续有效。验证范围见 `runs/build/studio-v1.3/verification.md`。
